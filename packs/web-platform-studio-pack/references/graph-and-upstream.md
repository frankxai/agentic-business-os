# Delivery graph and upstream selection

The kit projects one project's evidence into a dependency graph. It does not start agents or execute tools. Existing host orchestration, authority, memory, budgets and persistence remain responsible for runtime execution.

## Implemented mechanics

`delivery-graph.json` defines an initial scope gate, branches for identity/application/infrastructure, conditional commerce/application paths, convergence for independent review, and a final delivery/operations sequence. `graph.mjs` validates unique nodes, coverage, dependencies and acyclicity. A missing prerequisite blocks downstream work even when downstream receipts already declare a pass. Edition-inapplicable branches are explicitly skipped. `studio.mjs plan <workspace>` emits the current projection.

This implements procedural capability routing for the Foundry pack. In Starlight, Layer A workflow execution and its brakes remain in the existing SIS work/loop-graph owner. The output is a reviewable adapter input; it is not a verified SIS runtime integration. The schema makes no tool permissions, cost limits or release authority implicit. Layer B memory is not replaced by this file. Layer C code indexing and Layer D steering remain separate concerns.

For an eventual runtime adapter, bind the exact node artifact, owned files, actor, input/output schema, evidence write-back, timeout, retry/idempotency policy and applicable host brakes. Reject same-actor independent verification at the runtime boundary. A plan marked ready means its prerequisites are recorded; execution still needs host authorization. Do not turn an untrusted repository's instruction text into a higher-authority message.

## Source selection and provenance

`sources.json` records upstream links, observed revisions where available, license observations, adopted mechanics and boundaries. No third-party source code or complete skill text is vendored in this version. An unknown top-level license is not permission to redistribute; inspect the exact file's license before any later import. Commit pins document this research observation, rather than promising freshness forever.

Official Agent Skills guidance informs portable task packaging. Vercel's interface guidance informs accessible controls, focus, content overflow and motion. Anthropic's design guidance informs a subject-specific visual direction. The community Impeccable project informs separate product/design records and a deliberate refinement pass. LangGraph's persistence documentation informs the distinction between a graph picture and durable execution. These references do not establish that our implementation has inherited their testing or support.

Resolve conflicts explicitly: Starlight's sentence case rule takes precedence over an upstream title-case recommendation. Native semantic controls provide keyboard behavior without unnecessary custom key handlers. Review upstream suggestions against the actual interface and user task.

## Application in this version

The Studio website is a native static code starter with an in-browser brief builder. Its module list and plan are derived from the same acceptance definitions and delivery graph. It exports a draft project record that the CLI can validate. It keeps project details local to the page unless the user downloads them, and it deliberately leaves evidence empty. No real customer data, fabricated testimonials, earnings or unsupported certifications are seeded.

Before public release, inspect desktop/mobile and keyboard/touch behavior, complete an independent review and bind the final source revision to the host release packet. Preview output is noindex and has no checkout or unconnected lead form. Enabling a public business page requires the existing product/demand-capture and source-owner workflow.
