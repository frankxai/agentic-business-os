# Platform editions and boilerplate extraction

Choose by the buyer's editing model, business function, ownership needs, integration constraints and total cost. The table is an architectural routing proposal; validate current platform capabilities, export rules and seller terms before advertising compatibility.

| Delivery family | Candidate platforms | Native deliverable to build | Buyer journey to prove |
|---|---|---|---|
| Premium marketing/content | Framer, Webflow | Native editable project/template with CMS and interactions where required | Duplicate/import, edit brand/content, connect domain, publish |
| Owned code website | Next.js, Astro | Versioned repository, content model, design tokens, assets and deployment recipe | Clean install, customize, build and deploy |
| Commerce | Shopify; WordPress/WooCommerce when the job fits | Real native theme/integration with supported versions | Catalog, cart, payment, order, email, cancellation/refund |
| Business web application | Next.js or another justified framework with managed data/auth | Application code, schema, migrations, role policies and integration tests | Sign in, complete core task, recover failures, export/exit |
| Agentic platform | Application stack plus evaluated provider/tool layer | App + evaluations, permissions, durable jobs, metering and operations | Complete a bounded task under failure, isolation and cost constraints |
| AI-assisted rapid prototype | v0, Lovable, Bolt, Replit as selected tools | Actual generated/source project with ownership and dependency audit | Export/transfer, reproducible build and managed deployment |
| Existing business estate | WordPress, Wix Studio or customer's current platform | Native maintained implementation and migration plan | Customer edits safely and retains accounts/data |

The tool used to generate code and the platform used to deliver/run it are separate fields in a detailed architecture decision. Avoid multiplying near-identical products solely because different coding tools produced them.

## Where the offer belongs

FrankX showcases selected finished work and teaches the process. Starlight Studio presents the supported outcome and edition catalog. The applicable native marketplace distributes an actual native product. Existing code/digital delivery channels handle repositories and original assets. Tutorials may include suitable approved affiliate links. A marketplace listing and an affiliate recommendation should each accurately describe their separate relationship.

## First code edition to extract

Start from an existing maintained site whose source owner can supply a clean extraction. Preserve original authorship. Remove private data, branded assets without redistribution rights and account-specific assumptions. Package a coherent design with representative pages and content, theme tokens, responsive assets, image/metadata primitives, schema, accessible forms, a working primary CTA, analytics events and a verified deployment recipe.

For an application edition, add only the required layers: auth/session/recovery, database migrations, tenant policy where needed, transactional email, storage, jobs, payments/entitlements, settings/export/deletion, logging and error recovery. Use the project's actual compatible dependency versions and lockfile; never assemble a paid boilerplate from untested latest-version fragments.

The current repository already contains a business-site template and Foundry work. Reconcile those owners and gate results before extraction. This pack intentionally does not claim that an existing template is now release-ready just because it is discoverable.

## Native-builder edition gate

A native edition needs the actual editable project, supported components/CMS/interactions, legal redistribution rights, duplicate/import link, setup guide and a fresh-account buyer rehearsal. A screenshot, HTML ZIP or React export cannot substitute for a native Framer/Webflow product. Verify current marketplace submission requirements and commercial license terms.

## Supported-platform register

For each advertised edition retain: platform/version, native artifact ID/hash, source owner, tested customization path, deployment or publish evidence, integration limitations, asset/license ledger, last verification, update/support window, known defects and removal/deprecation policy. Only editions with this evidence become supported catalog entries.

Version 0.2.0 implements a **native static Studio code edition** with a local brief builder and portable exports. It implements zero native builder adapters and zero application backends. Its four review presets organize further implementations. The code edition's source-level checks and browser/independent review are recorded separately; its existence is not commercial release approval.
