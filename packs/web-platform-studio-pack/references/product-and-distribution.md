# Product architecture and commercial paths

Proposal dated 2026-09-24. Prices, demand, seller admission and revenue are unvalidated unless backed by a separate current product packet.

## Brand roles

**Sites by FrankX** is the public portfolio and editorial voice: finished work, honest case studies, demonstrations and technical stories. **Starlight Production Studio** is the delivery and product business: the kit, supported platform editions, template catalog and a bounded implementation practice. Retain the existing Starlight studio identity rather than creating another unrelated agency brand.

Candidate routes are FrankX's existing sites/work area and a Studio area on Starlight's canonical public site. Confirm actual route/source ownership before implementation. These names are recommendations, not assertions that pages have been deployed.

Use one approved project record to publish several appropriate views: live showcase, detailed case study, reusable template, workflow explanation, comparison/tutorial and operator handoff. Separate ownership: our product, client work with publication permission, collaboration with accurate attribution, and private reference. An owned demo is not a paying-client success story.

## Product ladder

| Offer | Buyer outcome | Paid value to validate | Release dependency |
|---|---|---|---|
| Open studio core | Start an organized project and see delivery gaps | Reach and activation; MIT source stays open | Documentation, tests and real onboarding |
| Native website editions | Customize and launch an excellent site on one chosen platform | Original native designs, assets, setup and maintained updates | Real native package and clean-user customization |
| App/platform editions | Build a secure business workflow with durable data | Tested integrations, migrations, evals, operations recipes | Complete deployed journey and negative tests |
| Brand and media packs | Consistent identity and launch assets | Original rights-cleared assets and reproducible production recipe | Rights, export formats, actual visual review |
| Search and content packs | Publish expert pages and measure discovery | Vertical expertise, reusable page models and measurement integration | Accurate content and instrumented baseline |
| Agency/operator kit | Repeat delivery across customers | Intake, scope, acceptance, updates, handoff, partner enablement | Second operator completes a clean install |
| Maintenance subscription | Keep a supported installation working | Defined update/support scope and measured support capacity | Update/rollback drill and sustainable service economics |
| Productized studio delivery | A completed bounded implementation | Scoped delivery using the same reusable kit | Real delivery capacity, contract and margin evidence |
| Tool referrals and affiliate content | Help buyers select tools for their situation | Approved commissions from relevant recommendations | Current terms, enrollment, disclosure and attribution |
| Future hosted builder | Configure and operate projects through software | Repeated workflow solved more efficiently | Demonstrated demand, isolation, economics and operations |

Platform-native templates, code starters, original visual assets, skills and managed services have different licensing and support needs. Bundle only what buyers can actually use together. A subscription must have continuing value and a maintained compatibility promise. A white-label entitlement needs explicit contractual rights; it cannot transfer ownership of third-party templates or customer work.

## Compounding production loop

1. Deliver one useful project for a specific buyer.
2. Obtain permission to show selected work and outcomes.
3. Extract general components, tests, runbooks and original asset systems.
4. Remove customer data, licensed restrictions and account assumptions.
5. Rebuild the native template through a clean buyer account.
6. Publish the approved case study and technical tutorial.
7. Connect the tutorial to the actual template and relevant approved tools.
8. Feed setup problems, support cost and outcomes into the next version.

Track contribution per offer: collected revenue minus refunds, payment/marketplace fees, infrastructure, model use and support/delivery labor. Record acquisition cost separately and also calculate contribution after acquisition. Value founder time explicitly. Use scenarios with stated assumptions; never present hypothetical income as current performance.

## Distribution and affiliate controls

Owned FrankX/Starlight pages explain the value. Use appropriate native marketplaces for native templates; use an existing approved digital-delivery rail for code/assets. Keep the product artifact, version, price/license and support promise consistent across channels. Preserve a direct delivery recovery path.

An affiliate program, expert-partner program, marketplace creator payout and referral credit are distinct arrangements. Recheck official terms and account admission before inserting a paid link. Store terms URL/date, eligible products/geographies, cash versus credits, attribution window, payout rules and permitted placement in the existing partner record. Disclose the relationship near recommendations; judge suitability independently of commission. Do not promise enrollment or payouts based on a public landing page.

## Build sequence and decision gates

1. Use the open core on one owned production site; prove a new operator can follow it.
2. Extract one premium code edition from an existing maintained source owner.
3. Validate one builder-native edition from buyer demand and native delivery economics.
4. Package operator workflows once a second person repeats the delivery.
5. Add recurring maintenance after measuring actual update/support burden.
6. Build hosted automation only for repeated work that the local kit cannot handle well.

Unreleased public products capture demand through the host's existing product-specific capture system. Paid checkout follows the release gate. At Starlight, retain independent provider critique, three-provider cold buyer execution for agentic products, delivery/recovery evidence and founder pricing approval. This kit's report cannot supply those decisions.
