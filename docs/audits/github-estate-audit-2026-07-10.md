## Duplicates and drift

1. **Academy duplication.** `frankxai/ai-architect-academy`, `frankxai/saas-ai-architect-academy`, `frankxai/aiarchitectacademy`, and the `AI-Architect-Academy` organization overlap. One `aiarchitectacademy` repo is empty. Canonicalize learning IP before adding features.
2. **Income-network ambiguity.** The intended split is sound—hub, technical spoke, disruption spoke—but local branches and the estate manifest classify spokes as possible archive candidates while active work continues. Preserve until the Domain Production lane decides.
3. **Manifest drift.** `agentic-business-os`, sales/marketing intelligence, and recent vertical product work were not represented consistently in the local estate control manifest at audit time.
4. **Helper drift.** The Agentic Income skill documents `scripts/audit-income-network.ps1`; the repo currently exposes `affiliate-audit.mjs` and `revenue-report.mjs` instead.
5. **Claim drift.** Some older business plans contain unverified revenue projections, future user counts, framework comparisons, or runtime adoption statistics. Treat them as hypotheses until re-verified.

## Fulfillment and experience gaps found live

- The local FrankX student OS route exists in source but its expected live route returned 404 and lacks a complete CTA/onboarding/download journey.
- FrankX has strong live/prototype merchandising surfaces, but several template, architecture, and creator-product routes still point to coming-soon, early-access, self-referential, or missing fulfillment paths.
- Agentic Income's direct paid offers depend on checkout, capture, analytics, and delivery configuration; the x402 route is a testnet/stub pattern, not production payment proof.
- Starlight Intelligence Academy is a newer operator-learning front door, but it should not replace the deep content library until its application, backend, and evidence path are complete.
- Hermes and swarm repos describe useful desired-state architectures. Treat them as implementation options, not proven always-on customer products, until a clean deployment recipe, heartbeat, evaluation, and support boundary are verified.

## Largest product gap

The current Foundry is optimized for application-based installs into meaningful businesses. It does not yet provide the full beginner-to-operator route requested here:

- no single Pathfinder that chooses a route;
- no seven-day proof experience;
- no runtime/architecture chooser;
- no general opportunity library;
- no explicit student or job-restart path;
- no generalized white-label operator contract;
- no proof-cell community layer;
- no consistent kit manifest covering license, support, security, tests, last verification, and deployment proof.

The property vertical already demonstrates most of this pattern. Generalize from working vertical evidence instead of inventing a new platform.

## Independent verification blockers

The following are not ready to sell as white-label or always-on products:

- The First Agent source inside the FrankX monorepo is an educational AI SDK 4 / Next.js 15 prototype. Its public chat endpoint lacks authentication, tenant isolation, rate limits, and spend caps; six linked standalone starter repositories returned 404 through authenticated GitHub lookup.
- Sales Intelligence and Marketing Intelligence are concepts represented only by README files. They need tools, fixtures, evaluation cases, and a real implementation receipt.
- The local Hermes profile layer describes more profiles and installation behavior than it currently ships. Distribution schema, license, installed-version compatibility, and whole-process isolation must be proven.
- ArcaneaClaw's packaging and security claims conflict with its current code and repository state: missing license artifacts, process execution, caller-provided scan paths, and failing lint on the latest main CI.
- OpenClaw forks are behind current upstream or have incomplete license evidence. Use pinned official upstream releases unless a fork has an explicit maintenance and provenance contract.
- MCP starter assets are useful developer tools, but remote SaaS use requires authentication, audience validation, narrow scopes, and isolation.

These findings do not invalidate the Foundry. They define the Foundry's trust advantage: evidence-bounded packaging, current adapters, explicit isolation, and stop/go gates.

## Recommended consolidation

1. Make `agentic-business-os` the canonical substrate.
2. Make FrankX Foundry the discovery and commercial front door.
3. Generalize the property implementer pattern into a domain-neutral operator contract.
4. Keep Agentic Income as a specialist acquisition and income-business example.
5. Keep AI Architect Academy as advanced learning and certification evidence.
6. Use Starlight Communities behind the scenes for cells, quests, memory, and proof rituals.
7. Require every kit to carry evidence, licensing, support, security, and update metadata before marketplace or white-label promotion.
